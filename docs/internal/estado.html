CLI, MCP y dashboard — cómo se hacen

Ejecución por CLI hecho

Requisito de elegibilidad: Trading API + (CLI o MCP). Cubierto.

Qué es. El binario oficial alpacahq/cli (pineado a v0.0.14). No tiene flag multi-pata, así que se usa el escape hatch alpaca api — misma request que probamos el Día 0, distinto transporte.

Cómo funciona ahora 
# agent/broker.py — cada llamada de trading sale por aquí
subprocess.run(["alpaca", "api", "POST", "/v2/orders",
                "--body", json.dumps(body), "--quiet"])

# condor de 4 patas, limit_price FIRMADO (negativo = crédito)
{"order_class": "mleg", "qty": "1", "type": "limit",
 "limit_price": "-1.10", "legs": [ ...4 legs... ]}
Instalar en local (para probar) 
curl -sL https://github.com/alpacahq/cli/releases/download/v0.0.14/\
cli_0.0.14_windows_amd64.zip -o alpaca.zip
# descomprimir, alpaca.exe al PATH, luego:
export MSYS_NO_PATHCONV=1   # Git Bash mutila las rutas /v2/...
alpaca api GET /v2/account
Lo que queda
  • Poner las keys de UC3M en los secrets de GitHub (no en .env).
  • El workflow ya instala, cachea y verifica la versión — solo hay que lanzarlo.

MCP — "ask the desk" opcional ~2–3 h

Cortado (issue #20). El CLI ya cumple el requisito. Se hace solo si Technology y Presentation ya están cerrados el miércoles.

Qué es. Un servidor MCP mínimo que expone el estado del desk como resources y un par de tools de solo lectura, para que un juez —o el vídeo— le pregunte a la mesa "¿por qué no has operado hoy?" y reciba una respuesta razonada del journal.

Forma mínima (Python, mcp SDK) 
# resources — solo lectura, cero riesgo
desk://state        # libro abierto: broker.positions() + trades.jsonl
desk://signal/{sym} # último Signal por subyacente
desk://journal      # últimos N eventos: rejected, debate, opened, exit
desk://predictions  # ledger de tesis calificadas

# tools
explain_last_decision(symbol)  # lee el journal, resume el stand-down / debate
why_no_trade_today()           # agrega los motivos de rejected del día
Pasos
  1. Reutiliza journal.py y broker.py — el MCP no calcula nada, solo lee lo que el loop ya escribió.
  2. Servidor stdio local para la demo; no hace falta desplegarlo.
  3. Registrarlo en la config del cliente MCP (Claude Desktop) para grabar el vídeo.
  4. Documentar en el write-up los recursos y tools exactos que expone.

Riesgo cero: si se rompe, no toca el trading. Solo sube Technology y da un plano de vídeo. No bloquea nada.

Dashboard "trading floor" opcional ~1 día

Las reglas dicen explícitamente que la UI no se evalúa. Último de la lista. Solo si el agente + write-up + vídeo están hechos.

Qué es. Una página que lee data/ del repo (que el cron commitea) y lo pinta: curva de equity, feed del debate, libro de posiciones, ledger de predicciones acertadas/falladas.

Forma más barata que funciona 
# NO Next.js. Una sola página estática que hace fetch del raw de GitHub:
fetch("https://raw.githubusercontent.com/alvaarocl/iv-desk/main/data/equity.csv")
fetch(".../data/journal.jsonl")

# deploy: GitHub Pages o Vercel estático. Cero backend, cero coste.
Secciones
  • Equity — sparkline de equity.csv, número grande del P&L.
  • La mesa — últimos eventos debate: tesis, veredicto de cada seat.
  • Libro — posiciones abiertas con strikes y max loss.
  • Ledger — predicciones cerradas, ✓/✗.

Si se hace, es contenido para redes (premio aparte) y un plano de vídeo. Pero cada hora aquí es una hora que no está en la calibración o el write-up, que sí puntúan.
